SQL的主线是从表中取出需要的数据：先看表结构，再写条件，再排序、计算、组合，最后读懂业务问题对应的查询。

知识主线

SQL与数据库查询

SQL本质上是在回答业务问题：“从哪张表，拿哪些列，满足什么条件，以什么顺序看结果”。学 SQL 要从表的形状开始，而不是一上来背语句。

读这个页面时，先抓住“为什么学、先学什么、下一步连接哪里”。这样知识会形成路线，而不是散落成单个名词。

表、列、行、NULL ↓ SELECT基本骨架 ↓ WHERE条件 ↓ 运算子与NOT ↓ 实习题转业务查询

学习路线

1

先看懂表的形状

数据库不是 Excel 截图，而是由表、列、行构成的数据模型。先分清列代表属性，行代表一条记录，NULL 代表没有值。

要掌握テーブル、カラム、レコード、NULL、主キー
怎么学拿一张表，先说出每列含义和一行数据代表什么
连接下一步表结构清楚后，SELECT 才知道从哪里拿数据
2

建立 SELECT 查询骨架

最小 SQL 思维是 SELECT 取列，FROM 指表，WHERE 加条件。先把骨架写稳，再谈复杂语法。

要掌握SELECT、FROM、WHERE、列指定、全件検索
怎么学每道题先划出“要显示的列”和“来源表”
连接下一步骨架稳定后，重点转向条件表达
3

把题意翻译成 WHERE 条件

WHERE 是把自然语言限制翻译成逻辑条件。大于、小于、等于、范围、文字匹配，本质都是筛选行。

要掌握比較演算子、AND、OR、BETWEEN、LIKE
怎么学把题目里的“以上、未満、含む、等しい”标成运算符
连接下一步条件会越来越复杂，下一步要处理否定和空值
4

理解 NOT 和 NULL 的陷阱

NOT 不是简单反着读，NULL 也不是 0 或空字符串。很多 SQL 错误来自把“不满足条件”和“不知道值”混在一起。

要掌握NOT、IS NULL、IS NOT NULL、三値論理
怎么学遇到 NULL 必须用 IS NULL，不用 = NULL
连接下一步避开陷阱后，就能进入综合实习题
5

用实习题连接业务查询

SQL01-30 的价值不是刷题数量，而是训练把业务需求稳定翻译成 SQL。每题都问：显示什么、从哪里来、筛选什么。

要掌握SQL実習、業務条件、結果確認、デバッグ
怎么学写完 SQL 后用结果行数和列名检查是否符合题意
连接下一步最终能把数据库查询接到系统设计和应用开发

这个板块解决什么：先理解数据如何以表、列、行保存。

典型例子：学生表中一行代表一个学生，一列代表一个属性。

  • 掌握标准：能说明每列含义和一行记录代表什么。
  • 常见误区：把表当作普通文本，不看字段意义。
  • 连接到：进入SELECT查询骨架。
